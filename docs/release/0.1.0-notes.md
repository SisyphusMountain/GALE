### The one failure

`tests/test_fraction_missing_hvp.py::test_hvp_fraction_missing_zero_bit_identical_to_none`

This test does a bit-exact (`torch.equal`) comparison of two independently computed
GPU Hessian-vector products that are mathematically supposed to take the same code
path. It failed here with a maximum absolute difference of `3.231e-27` — this is the
known, pre-existing GPU floating-point reduction-order nondeterminism documented for
this test (two runs of the same reduction on the GPU can sum values in a different
order and land a few ULPs apart at this magnitude). Not a correctness regression.

Re-run alone 3 times (`.venv/bin/python -m pytest "tests/test_fraction_missing_hvp.py::test_hvp_fraction_missing_zero_bit_identical_to_none" -q -p no:cacheprovider`):

- Run 1: passed
- Run 2: passed
- Run 3: passed

3/3 passed alone, consistent with the reported ~1-in-3 intermittent failure rate for
this specific bit-exact comparison. Library code and the test were not modified.

The other watched intermittent test, `test_certify_matches_dense_and_fisher_converges`
(memory-budget gated), did not fail or skip in this full run (it passed silently), so
the conditional CLI-end-to-end + memory-gated combined check was not needed.

  `rustree` package is installed in this venv, so tests that import it as a Python
  module skip): `tests/regression/test_global_recipe.py`,
  `tests/regression/test_newton_multibatch.py`, `tests/regression/test_perf_regression.py`,
  `tests/regression/test_simulate.py`, `tests/regression/test_specieswise_recipe.py`,
  `tests/test_hvp_multibatch.py`, `tests/regression/test_memory_gate.py` (2 skips in
  this file)
- 2x `archaea reference dataset is unavailable`: `tests/test_convergence_adaptive_solver.py`
- 4x `kernel-bench 666x80 capture not found at kernel-bench/data/666x80/whole.pt
  (set GPUREC_KB_CAPTURE)`: `tests/test_optim_golden.py`

All 14 skips are for data/artifacts absent from this machine (the archaea reference
dataset, the kernel-bench capture file) or for the `rustree` Python module not being
installed as a separate package in this venv (only its Rust crate, built in as part of
`gpurec-preprocess`). No test was skipped for any other reason.

### Warnings (25)

- 7x `RuntimeWarning: neumann tol=1.00e-07 is below the torch.float32 finite-precision
  residual floor 4.77e-07; clamping to the floor.` — expected: several tests
  (`test_alerax_layout.py::test_same_file_names`,
  `test_cli_end_to_end.py::test_global_fit_without_samples`,
  `test_config_rates.py::test_fit_genewise_still_uses_1e6_2p0_box`,
  `test_genewise_hvp.py::test_fit_genewise_converges_on_small_fixture`,
  `test_genewise_hvp.py::test_fit_genewise_converges_with_multibatch_analytic_hvp`,
  `test_interface_fit.py::test_global_fit_improves_the_likelihood`,
  `test_interface_fit.py::test_per_family_fit_improves_each_family`) run the E-adjoint
  Neumann solver in single precision (fp32) with the reference tolerance `1e-7`, which
  is below what fp32 can resolve, so gpurec clamps to the fp32 floor and warns once per
  run, exactly as documented in the changelog.
- 18x `DeprecationWarning: torch.jit.script is deprecated. Please switch to
  torch.compile or torch.export.` — all from `tests/test_centered_pi_so.py`, which
  exercises the TorchScript-compiled centered-pi kernel; this is a warning from PyTorch
  about its own deprecated API, not from gpurec's code.

No cause for concern in either group; neither is new or a regression.
