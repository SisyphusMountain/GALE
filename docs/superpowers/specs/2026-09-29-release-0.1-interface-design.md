# gpurec 0.1 release: user interface design

Date: 2026-09-29. Branch: `release/0.1`, created at commit `27cdc472`
(4 August 2026), the last development state before 1 September 2026.
Nothing committed after that date is brought into this branch.

## 1. Goal

Make the 4 August version of gpurec usable by someone who is not its author,
and release it as a tagged GitHub version (`v0.1.0`).

Two ways of using it, one implementation behind both:

1. **From a Python / PyTorch script**: load gene families, fit rates, read
   likelihoods, draw reconciliation samples, and keep access to the PyTorch
   module for custom optimization.
2. **From the command line with AleRax's arguments**: an AleRax 1.4.0
   command line works after replacing the program name `alerax` by `gpurec`,
   and gpurec writes the same output files under the output folder.

The numerical computation (the likelihood kernels and the gradient) is not
changed. The work is the interface, the input parsing, the bugs that block
fitting, reconciliation-sample output, internal cleanup and packaging.

## 2. What the 4 August version has today, and why it is not enough

Found by reading the code at `27cdc472` (the global-mode crash was confirmed
by reading `gpurec/fit/global_fit.py:44` against the `SolverOptions` class):

- `gpurec fit --mode global` crashes: `global_fit.py:44` passes the setting
  `e_adjoint_solver`, which `SolverOptions` no longer has.
- `gpurec fit --mode genewise` crashes on its first step when run from the
  command line: the command line always passes a config, whose rate cap
  `rates.max_rate` is `None`, and `genewise_fit.py:329` compares against it.
- Species-wise fitting is not reachable from files (`dtl_fit.py:78-84`).
- The families-file reader (`genewise_fit.py:69-83`) only recognises
  `starting_gene_tree =` lines; AleRax's `gene_tree = ...` form is returned
  as a literal path. `mapping =` lines are ignored.
- Gene-to-species mapping is hard-wired in Rust to "the part of the gene name
  before the first `_`" (`crates/gpurec-preprocess/src/lib.rs:514-524`); no
  mapping file is read. The README example cannot run under this rule.
- There are no AleRax-style arguments and no AleRax output folder.
- Reconciliation sampling exists (`sample_reconciliations`, Rust crate
  `gpurec-backtrack`, validated against AleRax 1.4.0's sampler in
  `tests/test_backtracking_matches_alerax.py`) but returns raw event lists for
  one sample of one family, with species as numbers; nothing writes files.
- Settings are read from environment variables in about a dozen places;
  output goes through ~56 `print` calls; research-only modules are in the
  installed package; about ten tests call functions that no longer exist;
  packaging lacks readme/license metadata and some data files.

## 3. Scope

In scope:

- Fitting with one shared set of rates (AleRax `GLOBAL`) or one set per
  family (AleRax `PER-FAMILY`).
- Likelihoods at fixed rates (AleRax `--fix-rates`).
- Reconciliation samples (AleRax `-g N`) with the per-sample trees, per-sample
  counts and summary files listed in section 6.
- AleRax-compatible input (families file, both mapping-file formats,
  fraction-missing file, AleRax's family filtering).
- Cleanup of the internals (section 8), packaging and release (section 9).

Out of scope for 0.1 (rejected with a clear error, section 5.3):
per-species rates, species-tree search, highways, transfer constraints other
than AleRax's default, origination other than uniform, the UndatedDL model,
the majority-rule consensus tree, `.alerec` files, `ccps/` and `checkpoint/`.

## 4. Python interface

New module `gpurec/interface.py` (public names re-exported from `gpurec`).
Every function takes every argument explicitly; the values used by the
command line come from AleRax's documented defaults and are written once,
as named constants in the command-line module (section 5).

```python
import gpurec

data = gpurec.load_families(
    families="families.txt",        # AleRax families file, a list of tree files, or a directory
    species_tree="species.nwk",
    min_covered_species=4,          # AleRax filtering rules (section 5.5)
    trim_ratio=0.0,
    max_clade_split_ratio=None,
    fraction_missing=None,          # path to an AleRax fraction-missing file, or None
)

fit = gpurec.fit(
    data,
    parametrization="global",       # "global" or "per-family"
    start_rates=(0.1, 0.1, 0.1),    # D, L, T
    config=gpurec.load_fit_config(None),   # solver, precision, memory settings; rate box [1e-6, 2]
)
fit.rates            # global: {"D": .., "L": .., "T": ..}; per-family: {family: {...}}
fit.log_likelihoods  # {family: natural-log likelihood}
fit.model            # the GeneReconModel (a torch.nn.Module)

ev = gpurec.evaluate(data, parametrization="global", rates=(0.1, 0.2, 0.05),
                     config=gpurec.load_fit_config(None))   # no fitting

samples = fit.sample_reconciliations(n=100, seed=123)   # also on `ev`
samples["fam1"][0]   # one ReconciledGeneTree

gpurec.write_alerax(result=fit, samples=samples, prefix="out/")
```

Objects:

- `FamilyData`: species tree (with AleRax node names, section 6.1), the
  retained families in AleRax order, their names, gene-to-species maps, and
  the families dropped by filtering with the reason.
- `FitResult`: `rates`, `log_likelihoods`, `model`, `parametrization`,
  optimizer history, wall time; method `sample_reconciliations(n, seed)`.
  `evaluate` returns the same type with no optimizer history.
- `ReconciledGeneTree`: nodes with gene name (leaves), species label, event
  (`S`, `SL`, `D`, `T`, `TL`, `Leaf`, loss nodes), children; methods used by
  the writers (RecPhyloXML, Newick, event counts, transfers).

Units: `log_likelihoods` are natural logs, as in AleRax's
`per_fam_likelihoods.txt` (same definition: uniform origination over the
species nodes, conditioned on survival). The values are gpurec's own and are
not expected to equal AleRax's. The PyTorch module keeps returning the negative
log-likelihood in bits; its docstring and the README say so explicitly.

`GeneReconModel`, `SolverOptions` and the rate-projection helpers remain
public for users who write their own optimization loop.

Device: gpurec runs only on a CUDA GPU, so no function and no command-line
option selects a device. Every entry point checks for a CUDA GPU first and
stops with a clear message if none is available. `GeneReconModel`'s existing
`device` argument is removed for the same reason.

Seeds: sample `i` of family `f` uses a random stream derived from
`(seed, f, i)`, so samples do not depend on batch layout or family order.
AleRax's own samples cannot be reproduced number for number: its random
numbers depend on the C++ standard library implementation.

## 5. Command line

Entry point `gpurec` (replacing the `reconcile` and `fit` subcommands).

```
gpurec -f families.txt -s species.nwk -p out/ --model-parametrization PER-FAMILY -g 100 --seed 42
```

### 5.1 AleRax arguments implemented

| Argument | AleRax default | gpurec behaviour |
|---|---|---|
| `-f/--families FILE` | required | families file (section 7.1) |
| `-s/--species-tree FILE` | required | Newick file; AleRax's named-tree options (`Random`, `MiniNJ`, ...) are rejected |
| `-p/--prefix DIR` | `alerax_output` | output folder |
| `--model-parametrization` | `GLOBAL` | `GLOBAL` or `PER-FAMILY` |
| `--d`, `--l`, `--t` | 0.1 each, must be > 0 | starting rates, or the rates used with `--fix-rates` |
| `--fix-rates` | off | evaluate likelihoods only |
| `-g/--gene-tree-samples N` | 100 | samples per family; 0 = no sampling |
| `--seed N` | 123 | sampling seed |
| `--fraction-missing-file FILE` | none | lines `species fraction`; must cover every leaf species |
| `--min-covered-species N` | 4 | AleRax filtering |
| `--trim-ratio r` | 0 | AleRax filtering |
| `--max-clade-split-ratio x` | -1 (off) | AleRax filtering |
| `--skip-family-filtering` | off | skip the file-readability checks, as in AleRax |
| `--verbose-opt` | off | log each optimizer step |

### 5.2 Accepted only with the value that describes gpurec's model

`--rec-model UndatedDTL`, `--transfer-constraint PARENTS`,
`--gene-tree-rooting UNIFORM`, `--origination UNIFORM`,
`--species-tree-search SKIP`. Any other value is an error.
(`PARENTS` is AleRax's name for "a transfer may not go to the donor or to
one of its ancestors", which is gpurec's rule.)

### 5.3 Rejected

Every other AleRax option (for example `--rate-optimizer`,
`--memory-savings`, `--cleanup-ccp`, `--highways`, `--no-tl`,
`--prune-species-tree`, `--speciation-gamma-categories`,
`--ccp-sample-frequency`, `--infer-speciation-order`) stops the program
before any work, with one message listing every unsupported option given.
An option that would silently do nothing is not accepted.

### 5.4 gpurec-only arguments

`--precision float32|float64`, `--config FILE` (TOML;
solver, memory and precision settings; section 8). They have no AleRax
counterpart.

### 5.5 Family filtering, as in AleRax 1.4.0

- Without `--skip-family-filtering`, a family whose gene-tree or mapping
  file cannot be opened, or is empty, is dropped with a logged message.
- `--min-covered-species N`: keep a family when it covers at least N species
  (counted from its mapping, or from the first tree's labels).
- `--trim-ratio r`: sort families by increasing clade count and keep the
  first `floor(N*(1-r))`.
- `--max-clade-split-ratio x` (when x > 0): keep a family when
  `x*(2*leaves-3) >= clades`.
- Dropped families appear in no output file; they are listed in the log.

## 6. Output files under `-p`

Unless stated, names, columns and row order match AleRax 1.4.0.

### 6.1 Species tree and node names

Internal nodes of the species tree that have no usable label (empty, equal to
another label, or a number such as a bootstrap value) are named as AleRax
does: `Node_<leftmost leaf of left child>_<leftmost leaf of right child>_<k>`,
with `k` counting from 0 until the name is unique, assigned in post-order.
These names are used in every file.

- `species_trees/starting_species_tree.newick`
- `species_trees/inferred_species_tree.newick` (identical, all branch
  lengths 1.0, as AleRax writes without species-tree search)

### 6.2 Likelihoods and rates

- `per_fam_likelihoods.txt`: `family logL` per line, natural log, sorted by
  increasing value then by name.
- `GLOBAL`: `model_parameters/model_parameters.txt`, header `node D L T`,
  one row per species node (2n-1 rows) in AleRax node order.
- `PER-FAMILY`: `model_parameters/<family>_rates.txt`, line 1 `D L T`,
  line 2 the three rates.

### 6.3 Other files

- `perSpeciesCoverage.txt`: `species fraction`, leaf species, sorted by
  increasing fraction then name.
- `gpurec.log`: the full command line, gpurec version, GPU name, filtering
  messages, optimizer progress, timings.

### 6.4 Reconciliation samples (`-g N`, N > 0)

`<i>` counts from 0, without padding.

- `reconciliations/all/<family>_sample_<i>.xml`: RecPhyloXML with the same
  header, elements and nesting as AleRax's writer: `<spTree>`, then
  `<recGeneTree>`; gene leaves named by gene, internal gene nodes `NULL`;
  events `leaf`, `speciation` (also for speciation-with-loss),
  `duplication`, `branchingOut` (transfer and transfer-with-loss), `loss`,
  and `transferBack` on the recipient branch.
- `reconciliations/all/<family>_samples.newick`: one sampled gene tree per
  line, internal nodes named by their event (`S`, `D`, `T`).
- `reconciliations/all/<family>_eventCounts_<i>.txt`: 8 lines `NAME:count`
  for `S SL D DL T TL L Leaf` (DL and L are 0, as in AleRax).
- `reconciliations/all/<family>_speciesEventCounts_<i>.txt`: header
  `species_label, speciations, duplications, losses, transfers, presence,
  origination, copies, singletons, transfers_to`; all-zero rows omitted.
- `reconciliations/all/<family>_transfers_<i>.txt`: `source destination 1`
  per transfer, in event order.
- `reconciliations/summaries/<family>_meanSpeciesEventCounts.txt` and
  `<family>_meanTransfers.txt`.
- `reconciliations/totalSpeciesEventCounts.txt`,
  `reconciliations/totalTransfers.txt`,
  `reconciliations/origins/<species>.txt` (one per species node).

### 6.5 Deliberate differences from AleRax

- Numbers are written at full precision, not AleRax's 6 significant digits;
  any parser of AleRax's files reads them.
- Rows of `speciesEventCounts_<i>.txt` are sorted by species name (AleRax's
  order there is unspecified; its summary files are already sorted).
- `<family>_samples.newick` has no branch lengths: gpurec's parsed clades do not keep the
  input trees' branch lengths.
- Not written: `ccps/`, `checkpoint/`, `alerax.log` (replaced by
  `gpurec.log`), `perSpeciesMissing.txt`, `.alerec`, `consensus_50.newick`.

## 7. Inputs

### 7.1 Families file (AleRax / GeneRax format)

Lines before `[FAMILIES]` are ignored; `#` starts a comment; whitespace is
removed from every line (as AleRax does, so paths cannot contain spaces);
`- name` starts a family; keys `gene_tree` or `starting_gene_tree` (a `.ale`
file or a file of Newick trees) and `mapping`; keys `alignment`,
`likelihoods` and `subst_model` are accepted and ignored because they only
concern sequence likelihoods, which gpurec does not use; any other key is
an error. Relative paths resolve against the current directory, as in
AleRax.

`load_families` additionally accepts a list of tree files or a directory
(`*.ale`, `*.newick`, `*.nwk`); family names are then the file names without
extension, and duplicate names are an error.

### 7.2 Gene-to-species mapping

- `mapping=` file whose first line contains `:`: `species:gene1;gene2;...`.
- Otherwise: `gene species` per line.
- No mapping file: the species is the part of the gene name before the first
  `_`; a name without `_` maps to the species of the same name.
- Every gene must map to a leaf of the species tree; otherwise the program
  stops, naming the family and the gene.

The Rust preprocessing (`gpurec-preprocess`) gains an optional per-family
gene-to-species table; when absent it keeps the current rule, which is
AleRax's default rule.

## 8. Internal cleanup

- Fix the global-mode and gene-wise-mode fitting crashes (section 2).
- Replace every environment-variable setting by a config field:
  `GPUREC_WARM_ADJOINT` (solver), `GPUREC_MEMORY_POLICY_FRACTION` and
  `GPUREC_MEMORY_POLICY_RESERVE_GIB` (memory), `NEWTON_FREE_CACHE_EVERY`,
  `NEWTON_TANGENT_SELF_ITERS`, `NEWTON_WST_NUM_WARPS` (newton). Remove
  `GPUREC_PREPROCESS_PATH` / `GPUREC_BACKTRACK_PATH`; the installed native
  modules are required. `fit_genewise` no longer writes to `os.environ`.
- Replace `print` by the `logging` module (logger name `gpurec`); the command
  line sends it to the screen and to `gpurec.log`.
- Move research-only code out of the installed package into a top-level
  `research/` folder: `gpurec/distributed.py`, `gpurec/fit/baselines.py`,
  `gpurec/fit/map_cv.py`, `gpurec/solver/_golden/`, `gpurec/docs/optim/`,
  `gpurec/bench/` (its AleRax readers move into the new input/output
  module). Anything still imported by production code stays.
- Tests that call removed functions: fix when the behaviour still exists,
  delete otherwise, and list each in the changelog.
- New code follows the "every argument explicit, no default values, no
  environment variables" rule. Existing internal functions keep their
  signatures; rewriting them is not part of this release.

## 10. Testing

CPU tests:

- Families-file reader: both tree keys, mapping, comments, ignored keys,
  unknown-key error, relative paths.
- Both mapping formats and the default rule; error for a gene whose species
  is not a leaf.
- Filtering rules against hand-computed expectations.
- Species node naming against the names in a species tree written by
  AleRax 1.4.0 for the same input.
- Argument handling: accepted values, the fixed-value options, the single
  rejection message.
- Each writer against small hand-checked expected files, and parsed back.

GPU tests:

- gpurec's likelihood values are NOT compared with AleRax's (the author's
  decision: AleRax's likelihoods are not a trusted reference). The existing
  numerical tests of the likelihood and gradient are kept as they are.
- Fitting (global and per-family) runs to completion on the fixtures and
  improves the log-likelihood over the starting rates.
- Sampling: the existing internal consistency test of the sampler
  (`tests/test_backtracking_statistical_consistency.py`) keeps running; the
  reconciled trees built from samples are checked for consistency (every
  gene leaf appears once, species labels are valid, event counts in
  `eventCounts` equal those in the RecPhyloXML file).
- Format checks against files written by AleRax 1.4.0
  (`/home/enzo/Documents/alerax_1_4/AleRax/build/bin/alerax`) on the
  fixtures under `tests/data/alerax/`: gpurec's RecPhyloXML files parse with
  a standard XML parser and use the same element names and nesting as
  AleRax's file for the same family (AleRax has no RecPhyloXML reader), and
  every other output file has the same name, header and column layout.
  Only the layout is compared, never the numbers.
- End-to-end command-line run: every file in section 6 exists and parses.

Before tagging: the whole test suite on the RTX 4090; the results are
recorded in the release notes.
